# Практическая работа №6. Разработка web-приложения ASP.NET Core MVC

Выполнил: Костин Даниил Антонович

## 1. Формулировка задания

По заданию практики №6 требуется реализовать web-приложение на ASP.NET Core MVC для
работы с данными одной предметной области, состоящей из основной сущности и связанной
с ней дополнительной сущности. Приложение должно:

- хранить данные через Entity Framework Core в реальной базе данных;
- предоставлять полный CRUD (добавление, редактирование, удаление, просмотр) для
  основной сущности, а также поиск и фильтрацию по её полям;
- иметь два контроллера — по числу сущностей — с фиксированным набором методов
  (`All`, `Add`, `Edit`, `Remove`, `Details`, `Stat`, для основной сущности также
  `Export` и `Filter`);
- работать с данными через интерфейс репозитория (`INoteRepository`), а не напрямую
  через `DbContext` в контроллерах;
- иметь строго типизированные `.cshtml`-представления для каждого действия и стартовую
  страницу со ссылками на разделы приложения.

## 2. Мой вариант

Вариант вычислен по формуле `V = (C1 + C2) % 14`, где C1, C2 — числовые коды (Unicode)
первых букв имени и фамилии на русском языке в верхнем регистре (тот же подход к
приведению `char → int`, что и в уже принятой практике №2, см.
`D:\ТРПО\КостинДА_2пр\пр2\ConsoleApp1\Utils\VariantCalculator.cs`, где используется
формула `(k1 + k2) % 11`).

- Имя «Даниил» → первая буква «Д» → код 1044.
- Фамилия «Костин» → первая буква «К» → код 1050.
- Сумма: 1044 + 1050 = 2094.
- 2094 % 14 = 8.
- Индекс 8 в таблице вариантов практики №6 соответствует варианту **В3.1**.

Вариант В3.1 — приложение **Notes** (заметки):

- основная сущность `Note (int Id, string Title, string Description, DateTime Date,
  List<Category> Categories)`;
- связанная сущность `Category (int Id, string Title, string Description,
  List<Note> Notes)` — в тексте задания у преподавателя здесь опечатка
  (`List<Card> Cards`, явно скопированная из раздела про FlashCards), для Notes
  корректно `List<Note> Notes`, что и реализовано в проекте;
- связь между Note и Category — многие-ко-многим: у заметки может быть несколько
  категорий, у категории — несколько заметок;
- фильтрация по варианту В3.1 использует OR-логику: заметка попадает в результат,
  если хотя бы одно из переданных слов встречается в `Title` ИЛИ в `Description`,
  без учёта регистра.

## 3. Реализация

### 3.1. Архитектура

```
Lab6/
  Models/
    Note.cs        — основная сущность
    Category.cs     — связанная сущность
  Data/
    NoteContext.cs        — DbContext (EF Core)
    INoteRepository.cs    — интерфейс репозитория
    EFNoteRepository.cs   — реализация репозитория через EF Core
  Controllers/
    NoteController.cs
    CategoryController.cs
    HomeController.cs
  Views/
    Note/    (All, Add, Edit, Details, Stat, Filter)
    Category/(All, Add, Edit, Details, Stat)
    Home/Index.cshtml
    Shared/_Layout.cshtml
  Migrations/         — миграции EF Core (InitialCreate)
  Program.cs           — DI, применение миграций, засев демоданных
```

Все контроллеры получают `INoteRepository` через конструктор (Dependency Injection),
никакого прямого обращения к `DbContext` из контроллеров нет — это единственная точка
доступа к данным, как того требует задание.

### 3.2. Провайдер базы данных: SQLite вместо MS SQL Server

В тексте задания упомянут MS SQL Server, но на машине, где выполнялась и будет
защищаться работа, нет установленного экземпляра SQL Server (ни полного, ни
LocalDB), а разворачивать сервер СУБД ради учебной сдачи одной практической работы
нецелесообразно — это лишняя инфраструктурная зависимость, из-за которой проект
переставал бы запускаться на любой другой машине без предварительной установки и
настройки SQL Server.

Вместо этого использован пакет `Microsoft.EntityFrameworkCore.Sqlite`. Это
полноценный, официально поддерживаемый провайдер EF Core: та же модель `DbContext`/
`DbSet`, тот же механизм миграций (`dotnet ef migrations add`, `Database.Migrate()`),
тот же LINQ-to-Entities поверх реальной базы данных на диске (`notes.db`). Отличие
только в строке подключения (`Data Source=notes.db` вместо `Server=...;Database=...`)
и в имени NuGet-пакета — сама архитектура репозитория, контроллеров и представлений
от выбора провайдера не зависит. При необходимости замены на SQL Server достаточно
поменять пакет и `UseSqlite` на `UseSqlServer` с соответствующей строкой подключения.

### 3.3. Модели и связь many-to-many

`Note` и `Category` — обычные POCO-классы с DataAnnotations-валидацией
(`[Required]`, `[StringLength]`). Связь многие-ко-многим настроена явно в
`NoteContext.OnModelCreating` через Fluent API:

```csharp
modelBuilder.Entity<Note>()
    .HasMany(n => n.Categories)
    .WithMany(c => c.Notes)
    .UsingEntity(j => j.ToTable("NoteCategory"));
```

EF Core создаёт промежуточную таблицу `NoteCategory` с двумя внешними ключами
(`CategoriesId`, `NotesId`) и составным первичным ключом — это видно в миграции
`Migrations/20260922222139_InitialCreate.cs`.

### 3.4. Репозиторий

`EFNoteRepository` реализует `INoteRepository` (сигнатура интерфейса зафиксирована
заданием):

```csharp
public interface INoteRepository
{
    IEnumerable<Note> GetAllNotes();
    bool AddNote(Note obj);
    bool RemoveNote(Note obj);
    bool UpdateNote(Note obj);
    IEnumerable<Category> GetCategories();
    bool AddCategory(Category category);
    bool RemoveCategory(Category category);
    bool UpdateCategory(Category category);
}
```

`AddNote`/`AddCategory` перед вставкой проверяют дублирование: заметка (категория)
не добавляется, если уже существует запись с тем же `Id`, либо совпадают все
остальные поля (для заметки — `Title`, `Description`, `Date`). Метод
`UpdateNote`/`UpdateCategory` находит существующую запись по `Id`, обновляет поля и
для заметки — пересобирает список связанных категорий.

### 3.5. Контроллеры

`NoteController`:

- `All(int n, string sort)` — список заметок с сортировкой по `Id`/`Title`/
  `Description`/`Date` (`sort == null` → по `Id`) и ограничением количества (`n == 0`
  → все записи); значения выставлены в `ViewData["Sort"]`, `ViewData["N"]`;
- `Add()`/`Add(Note obj, int[]? categoryIds)` — добавление заметки с выбором
  категорий чекбоксами; при успехе показывается страница статистики (как `Stat`);
  при дублировании или ошибке валидации форма возвращается с сообщением об ошибке;
- `Edit(int id)`/`Edit(Note obj, int[]? categoryIds)` — редактирование с
  предзаполненными выбранными категориями;
- `Remove(int id)` — удаление по `Id`;
- `Details(int id)` — полная информация без возможности редактирования, включая
  список связанных категорий;
- `Stat()` — статистика: `ViewData["Count"]` (число заметок), `ViewData["Date"]` —
  массив `[min, max]` по полю `Date`, `ViewData["Titles"]` — список уникальных
  заголовков;
- `Export(int n, string sort)` — та же выборка, что и в `All`, сериализуется через
  `System.Text.Json` (с `ReferenceHandler.IgnoreCycles`, чтобы разорвать цикл
  `Note.Categories ↔ Category.Notes`) и отдаётся файлом `notes.json`
  (`application/json`);
- `Filter(List<string> searchWords)` — реализует OR-логику варианта В3.1: заметка
  попадает в результат, если хотя бы одно слово из `searchWords` встречается в
  `Title` ИЛИ `Description` (`StringComparison.OrdinalIgnoreCase`). Список слов на
  странице `Filter.cshtml` вводится одной строкой через запятую и на клиенте перед
  отправкой формы разбивается небольшим JS-скриптом на несколько query-параметров
  `searchWords`, которые ASP.NET Core модель-байндер собирает обратно в
  `List<string>`.

`CategoryController` реализует аналогичный набор действий (`All`, `Add`, `Edit`,
`Remove`, `Details`, `Stat`) для дополнительной сущности — по заданию «до 100%» UI
должен поддерживать полноценную работу как с основной, так и с дополнительной
сущностью, поэтому у категорий также полный CRUD.

### 3.6. Program.cs, DI и миграции

```csharp
builder.Services.AddDbContext<NoteContext>(o => o.UseSqlite(connectionString));
builder.Services.AddScoped<INoteRepository, EFNoteRepository>();
```

При старте приложения (до `app.Run()`) поднимается scope, вызывается
`context.Database.Migrate()` (создаёт `notes.db` и применяет все миграции, если базы
ещё нет) и метод `SeedData`, который при пустой базе добавляет 3 демонстрационные
категории и 4 демонстрационные заметки со связями многие-ко-многим — это сделано для
удобства проверки работы сразу после первого запуска.

### 3.7. Представления

Для каждого метода действия есть строго типизированное представление (`@model Note`
/ `@model Category` / `@model List<Note>` и т.д.), таблицы оформлены Bootstrap-ом
из штатного шаблона `dotnet new mvc`. На `Views/Home/Index.cshtml` — три ссылки:
«Заметки» (`Note/All`), «Категории» (`Category/All`), «Фильтрация» (`Note/Filter`).
На каждой остальной странице есть ссылка «На главную», а в общей навигации
`_Layout.cshtml` — пункты «Заметки», «Категории», «Фильтрация».

## 4. Как запустить

Требуется установленный .NET SDK (проверено на 10.0.201).

Из корня решения:

```
dotnet run --project Lab6/Lab6.csproj
```

либо через решение:

```
dotnet build КостинДА_6пр.sln
dotnet run --project Lab6/Lab6.csproj
```

При первом запуске автоматически создаётся файл базы данных `Lab6/notes.db`,
применяются миграции и добавляются демонстрационные данные. После старта Kestrel в
консоли будет выведен адрес (например, `http://localhost:5189`) — его нужно открыть
в браузере. Стартовая страница ведёт на списки заметок, категорий и страницу
фильтрации.

В `.vscode/launch.json` добавлены конфигурации запуска для VS Code (аналогично
практике №1).

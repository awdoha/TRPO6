Чаще всего звучит SOLID, особенно **D — зависимость от абстракций**. Ниже — подготовка.

### 7.1. Что такое MVC и роли M, V, C
MVC (Model-View-Controller) разделяет приложение на три части. **Model** — данные и правила работы с ними: у меня `Note` и `Category` (`Models\Note.cs:9`, `Models\Category.cs:11`) и репозиторий (`Data\EFNoteRepository.cs:12`). **View** — то, что видит пользователь: Razor-файлы `.cshtml`, например `Views\Note\All.cshtml`, они только выводят данные. **Controller** — принимает HTTP-запрос, обращается к модели и выбирает представление: `NoteController.cs:16`. Смысл разделения: можно менять внешний вид, не трогая логику, и наоборот; удобнее тестировать. Мини-пример: `/Note/All` → `NoteController.All` (`NoteController.cs:34`) берёт список из репозитория и возвращает `View(notes.ToList())` → `All.cshtml` рисует таблицу.

### 7.2. Путь запроса: routing → контроллер → действие → представление
Пользователь вводит `/Note/Edit/3`. Middleware `UseRouting` (`Program.cs:61`) сопоставляет URL с шаблоном `{controller=Home}/{action=Index}/{id?}` (`Program.cs:71`): `Note` → `NoteController`, `Edit` → метод `Edit`, `3` → параметр `id`. Если сегментов нет, берутся значения по умолчанию (`/` = `Home/Index`). Для одного URL может быть два метода: GET и POST различаются атрибутами `[HttpGet]`/`[HttpPost]`. Контроллер создаёт DI-контейнер и подставляет зависимости в конструктор. Действие (`NoteController.cs:101`) возвращает `View(note)`, MVC ищет `Views\Note\Edit.cshtml`, оборачивает его в `_Layout.cshtml` (`_ViewStart.cshtml`) и отправляет HTML в браузер.

### 7.3. Как контроллер получает репозиторий (DI); время жизни; почему AddScoped
Контроллер объявляет конструктор `NoteController(INoteRepository repository)` (`NoteController.cs:24`). Сам объект не создаётся оператором `new`: его создаёт DI-контейнер ASP.NET Core на каждый запрос, увидев зависимость. Что подставить, задано в `Program.cs:29`: `AddScoped<INoteRepository, EFNoteRepository>()`. Времена жизни: **Singleton** — один экземпляр на всё приложение; **Scoped** — один на HTTP-запрос; **Transient** — новый при каждом обращении. `DbContext` регистрируется как Scoped (`AddDbContext`, `Program.cs:26`): он не потокобезопасен и хранит отслеживаемые изменения, поэтому должен жить не дольше запроса. Репозиторий держит ссылку на контекст, значит должен быть не «длиннее» его: Scoped (Singleton-репозиторий с Scoped-контекстом был бы ошибкой). Пример: в одном запросе контроллер и репозиторий получают один и тот же `NoteContext`.

### 7.4. Зачем интерфейс INoteRepository (принципы D и O)
Контроллер работает с `INoteRepository` (`Data\INoteRepository.cs:10`), а не с `EFNoteRepository`. **D (Dependency Inversion):** высокоуровневый код (контроллер) зависит от абстракции, а не от конкретного класса. **O (Open/Closed):** можно добавить новую реализацию (например, `InMemoryNoteRepository` для тестов или репозиторий для SQL Server) и заменить одну строку в `Program.cs:29`, не переписывая контроллеры. Плюс — тестируемость: в тесте подставляется «заглушка». Мини-пример: `builder.Services.AddScoped<INoteRepository, InMemoryNoteRepository>();` — контроллеры менять не надо.

### 7.5. DbContext, DbSet, миграции, Migrate vs EnsureCreated
`NoteContext : DbContext` (`Data\NoteContext.cs:12`) — сессия работы с БД: отслеживает изменения объектов, превращает LINQ в SQL, сохраняет `SaveChanges()`. `DbSet<Note> Notes` (`NoteContext.cs:20`) — «таблица» как коллекция, с которой пишут запросы. **Миграция** — C#-файл с шагами изменения схемы (`Up`/`Down`), создаётся `dotnet ef migrations add ИмяМиграции`; лежит в `Migrations`. `Database.Migrate()` (`Program.cs:41`) применяет все ещё не применённые миграции и записывает их в `__EFMigrationsHistory`. **EnsureCreated** просто создаёт схему «с нуля» по модели, без истории; потом не умеет её менять (только удалить и создать заново) и несовместим с миграциями. Поэтому для приложений, где схема будет меняться, используют `Migrate`.

### 7.6. Связь many-to-many и навигационные свойства
У `Note` есть `List<Category> Categories` (`Models\Note.cs:34`), у `Category` — `List<Note> Notes` (`Models\Category.cs:31`). Это **навигационные свойства**: по ним EF ходит по связям. Связь настроена Fluent API в `NoteContext.cs:37-39`: `HasMany(n => n.Categories).WithMany(c => c.Notes).UsingEntity(j => j.ToTable("NoteCategory"))`. В БД появляется промежуточная таблица `NoteCategory` (`NotesId`, `CategoriesId`, составной PK, два FK с каскадным удалением) — см. миграцию `InitialCreate.cs:72-111`. Отдельный класс для промежуточной таблицы не нужен (skip-навигация EF Core 5+). Пример: `Categories = [study, work]` в `SeedData` (`Program.cs`) — EF сам вставит две строки в `NoteCategory`.

### 7.7. ТРИ СПОСОБА ЗАГРУЗКИ СВЯЗАННЫХ ДАННЫХ В EF CORE (вопрос 24)
По умолчанию EF **не** подгружает связанные сущности: `Categories` у заметки была бы пустой. Способов три.

**1) Eager loading (жадная) — `Include` / `ThenInclude`. ИСПОЛЬЗОВАН В ПРОЕКТЕ.** Связанные данные загружаются тем же запросом (JOIN). Место: `EFNoteRepository.cs:30` (`Include(n => n.Categories)`) и `:124` (`Include(c => c.Notes)`).
```csharp
// заметки вместе с категориями
var notes = _context.Notes.Include(n => n.Categories).ToList();
// категории с заметками и категориями этих заметок (ThenInclude идёт «вглубь»)
var cats = _context.Categories.Include(c => c.Notes).ThenInclude(n => n.Categories).ToList();
```

**2) Explicit loading (явная) — `Entry(...).Collection(...).Load()`.** Сначала загружаем основной объект, потом отдельным запросом по требованию подгружаем связь. В проекте не используется.
```csharp
var note = _context.Notes.First(n => n.Id == 1);             // категории пока НЕ загружены
_context.Entry(note).Collection(n => n.Categories).Load();   // второй запрос: загрузили Categories
var cat = _context.Categories.First(c => c.Id == 1);
_context.Entry(cat).Collection(c => c.Notes).Query().Where(n => n.Date > DateTime.Today).Load(); // с условием
```
(для одиночной связи — `Entry(x).Reference(x => x.Prop).Load()`; объект должен отслеживаться, у меня в `GetAllNotes` стоит `AsNoTracking`, поэтому там так не получится).

**3) Lazy loading (ленивая) — через прокси.** Нужен пакет `Microsoft.EntityFrameworkCore.Proxies`, `options.UseLazyLoadingProxies()` и `virtual` навигационные свойства; связь подгружается автоматически при первом обращении. В проекте не используется.
```csharp
// Program.cs: options.UseSqlite(cs).UseLazyLoadingProxies()
// Note.cs:    public virtual List<Category> Categories { get; set; } = [];
var note = _context.Notes.First();
var count = note.Categories.Count;   // здесь неявно выполнится SELECT по категориям
```
Минус: проблема **N+1** — на каждую заметку в цикле уйдёт отдельный SQL-запрос. Поэтому в проекте выбрана eager-загрузка: в таблице `All` категории нужны для каждой строки, и один запрос с JOIN лучше N запросов.

### 7.8. Передача данных из контроллера в представление (ViewData, ViewBag, TempData, модель)
- **Модель** — строго типизированный способ: `return View(notes.ToList())` (`NoteController.cs:44`) и `@model List<Note>` в представлении. Основные данные лучше передавать так.
- **ViewData** — словарь `ViewData["Sort"] = sort` (`NoteController.cs:40`), читается в представлении с приведением типа (`ViewData["Sort"] as string`). Живёт один запрос.
- **ViewBag** — динамическая обёртка над тем же ViewData: `ViewBag.Categories = ...` (`NoteController.cs:53`), читается `ViewBag.Categories as List<Category>`. Без проверки типов на этапе компиляции.
- **TempData** — хранилище, которое переживает **редирект** (данные сохраняются до следующего запроса, обычно на cookie/сессии): удобно для сообщения «Сохранено» после `RedirectToAction`. В моём проекте TempData не используется.
Отличие: ViewData/ViewBag живут в пределах одного запроса, TempData — между двумя (через редирект).

### 7.9. Строго типизированные представления `@model`
`@model Note` в первой строке (`Views\Note\Add.cshtml:3`) говорит Razor, какого типа `Model`. Компилятор проверяет обращения (`Model.Title`, `Model.Date.ToString(...)`), в редакторе работает автодополнение, опечатку в имени свойства найдёт сборка, а не пользователь. `@using Lab6.Models` в `_ViewImports.cshtml` позволяет писать `Note`, а не `Lab6.Models.Note`. Пример: `@model List<Note>` в `All.cshtml` → `@foreach (var note in Model)`.

### 7.10. Razor и tag helpers
Razor — шаблонизатор: HTML с вставками C# через `@` (`@note.Title`, `@foreach`, `@if`, `@{ ... }`). Код выполняется на сервере, браузер получает готовый HTML; `@* ... *@` — комментарии Razor, в HTML не попадают. **Tag helpers** — «умные» атрибуты `asp-*`: `asp-controller`/`asp-action`/`asp-route-id` строят адрес по маршруту (`asp-action="Edit" asp-route-id="@note.Id"` → `/Note/Edit/5`); `asp-for="Title"` создаёт `<input name="Title" id="Title" value="...">` и подпись; `asp-validation-for` и `asp-validation-summary` выводят ошибки `ModelState`; `<form asp-action>` добавляет antiforgery-токен; `asp-items` строит `<option>` из `SelectList`; `asp-append-version` добавляет хэш к css/js. Подключены в `_ViewImports.cshtml` строкой `@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers`. Общий макет — `_Layout.cshtml` (`RenderBody()`), подключается через `_ViewStart.cshtml`.

### 7.11. [HttpGet]/[HttpPost] и AntiForgery
`Add()` с `[HttpGet]` (`NoteController.cs:50`) показывает форму, `Add(Note obj, int[]? categoryIds)` с `[HttpPost]` (`:64`) принимает данные. Имя одно, различает HTTP-метод. GET безопасен и идемпотентен (ничего не меняет), POST изменяет данные. `[ValidateAntiForgeryToken]` (`:61`) защищает от **CSRF** — когда чужой сайт заставляет браузер пользователя отправить POST на наше приложение: tag helper `<form asp-action>` кладёт в форму скрытый токен (и cookie), а атрибут сверяет их; нет токена — ответ 400. После успешного POST делается `RedirectToAction` (`:142`) — паттерн Post-Redirect-Get: обновление страницы не отправит форму повторно.

### 7.12. Валидация: ModelState и DataAnnotations
Правила описаны атрибутами на модели: `[Required(ErrorMessage = "...")]`, `[StringLength(200)]` (`Models\Note.cs:15-22`), `[Display(Name = "Дата")]`. Model binding заполняет `obj` из формы и проверяет атрибуты; результат — `ModelState`. В действии: `if (!ModelState.IsValid) return View(obj);` (`NoteController.cs:67-73`) — форма показывается снова с введёнными данными. Сообщения выводят `asp-validation-for` и `asp-validation-summary` в `Add.cshtml`. Свою ошибку добавляют так: `ModelState.AddModelError(string.Empty, "Такая заметка уже существует...")` (`NoteController.cs:84`) — используется при дубликате. Валидация в проекте серверная (клиентские скрипты `_ValidationScriptsPartial` не подключены).

### 7.13. Почему SQLite, а не SQL Server, и что менять
На машине нет SQL Server (ни полного, ни LocalDB), разворачивать сервер ради практики нецелесообразно. SQLite — полноценный провайдер EF Core: та же модель, `DbContext`, миграции и LINQ, а БД — один файл `notes.db`. Чтобы перейти на SQL Server: (1) заменить NuGet-пакет `Microsoft.EntityFrameworkCore.Sqlite` на `Microsoft.EntityFrameworkCore.SqlServer` (`Lab6.csproj`); (2) `UseSqlite` → `UseSqlServer` (`Program.cs:26`); (3) строка подключения в `appsettings.json`, например `Server=(localdb)\\mssqllocaldb;Database=Notes;Trusted_Connection=True;`; (4) удалить папку `Migrations` и создать заново `dotnet ef migrations add InitialCreate` (миграции привязаны к провайдеру: типы столбцов SQLite `TEXT`/`INTEGER` не подойдут). Контроллеры, представления и репозиторий менять не нужно.

### 7.14. Как работает Filter (OR) и как переделать в AND (вариант В3.2)
`Filter(List<string>? searchWords)` (`NoteController.cs:205`): пустые слова отбрасываются, остальные обрезаются (`Trim`); если слова есть, применяется `notes.Where(note => words.Any(w => note.Title.Contains(w, OrdinalIgnoreCase) || note.Description.Contains(w, OrdinalIgnoreCase)))` (`:225-229`). `Any` = «хотя бы одно слово подошло» → заметка проходит, если **одно из слов** есть в заголовке **или** в описании. Пример: слова «лекции, zzzz» найдут «Повторить лекции по БД». Слова приходят как несколько параметров `searchWords` — их создаёт скрипт в `Filter.cshtml:99-131`. **Переделка на AND** (все слова должны встречаться): заменить `words.Any` на `words.All`:
```csharp
notes = notes.Where(note => words.All(w =>
    note.Title.Contains(w, StringComparison.OrdinalIgnoreCase) ||
    note.Description.Contains(w, StringComparison.OrdinalIgnoreCase)));
```
(слово может быть в любом из двух полей). Если по условию AND нужно, чтобы все слова были именно в одном поле — вынести проверки: `words.All(w => Title.Contains(w)) || words.All(w => Description.Contains(w))`; уточняйте формулировку В3.2. Текст подсказки в `Filter.cshtml` («хотя бы одно из слов») тоже поменять.

### 7.15. Почему Add исключает дубли
Задание требует не добавлять запись, если такой Id уже есть либо совпадают все остальные поля. В `EFNoteRepository.AddNote` (`:37-45`) выполняется `_context.Notes.Any(n => n.Id == obj.Id || (n.Title == obj.Title && n.Description == obj.Description && n.Date == obj.Date))` — SQL `EXISTS`. Если найдено — возвращается `false`, и контроллер (`NoteController.cs:84`) добавляет ошибку в `ModelState` и показывает форму. Для категорий — то же по `Title` + `Description` (`EFNoteRepository.cs:134`). Показать: добавить заметку дважды с одинаковыми данными.

### 7.16. Export и ReferenceHandler.IgnoreCycles
`Export` (`NoteController.cs:178`) берёт ту же выборку, что `All`, и сериализует `JsonSerializer.Serialize(notes, options)` в JSON, затем возвращает файл `File(bytes, "application/json", "notes.json")` (`:196`) — браузер скачивает его. Проблема: `Note` → `Categories` → у `Category` есть `Notes` → снова `Note` — цикл; обычный сериализатор бросил бы исключение. `ReferenceHandler.IgnoreCycles` (`:189`) обрывает цикл: повторная ссылка на уже сериализуемый объект пропускается. Пример результата: у заметки есть массив `Categories`, а внутри категории поле `Notes` пустое или без повторов.

### 7.17. Отложенное выполнение: IQueryable vs IEnumerable (ToList) в репозитории (вопрос 11)
`_context.Notes` — это `IQueryable<Note>`: запрос **не выполняется**, пока его не «материализуют» (`ToList()`, `First...`, `Any`, `foreach`). Цепочка `Include(...).AsNoTracking()` только строит запрос; SQL уходит в БД на `ToList()` (`EFNoteRepository.cs:34`). Репозиторий возвращает `IEnumerable<Note>` — уже готовый список в памяти, поэтому дальнейшие `Where`/`OrderBy`/`Take` в контроллере (`NoteController.cs:225`, `:243`) — LINQ to Objects, выполняются в памяти, а не в SQL. Плюс подхода — контроллер не зависит от EF и запрос не «утекает» за пределы контекста (контекст живёт до конца запроса; ленивый `IQueryable` после освобождения контекста упадёт). Минус — для больших таблиц лучше фильтровать в БД (`Where` до `ToList`). Экзаменационная суть: **IQueryable** — фильтры транслируются в SQL (выражения `Expression<Func<>>`), **IEnumerable** — фильтры в памяти (делегаты `Func<>`); отложенное выполнение — запрос выполняется не при создании, а при переборе.

### 7.18. Асинхронность (вопрос 18): async/await и ToListAsync, почему в проекте синхронно
Асинхронные операции с БД освобождают поток на время ожидания ответа: `public async Task<IActionResult> All() { var notes = await _context.Notes.ToListAsync(); ... }` — поток возвращается в пул и обслуживает другие запросы; сервер выдерживает больше одновременных пользователей. **В проекте всё синхронно** (`ToList`, `SaveChanges`, `IActionResult` без `async`): интерфейс `INoteRepository` задан заданием с синхронными методами (`IEnumerable<Note> GetAllNotes()`, `bool AddNote(...)`), а приложение учебное, с одним пользователем и SQLite-файлом, где выигрыша нет. Чтобы сделать асинхронным: методы репозитория → `Task<IEnumerable<Note>> GetAllNotesAsync()`, внутри `await ... .ToListAsync()` / `await SaveChangesAsync()`, действия контроллера → `async Task<IActionResult>`.

### 7.19. Запасные вопросы (быстро)
- **Что такое Kestrel?** Встроенный веб-сервер ASP.NET Core, слушает порт из `launchSettings.json`.
- **Что такое middleware?** Звенья конвейера обработки запроса (`UseRouting`, `UseAuthorization`, `MapControllerRoute` в `Program.cs`).
- **Что делает `SeedData`?** Если БД пуста — добавляет 3 категории и 4 заметки (`Program.cs:85`).
- **Почему для Edit/Remove берём запись через `FirstOrDefault` из БД, а не `Update(obj)`?** Чтобы обновлять только то, что нужно, и правильно пересобрать связи many-to-many (`EFNoteRepository.cs:90-116`).
- **Почему в `GetAllNotes` `AsNoTracking`?** Данные только читаются для показа; отслеживание изменений не нужно, запрос быстрее.
- **Что делает `AttachCategories`?** Из формы приходят только Id категорий; метод достаёт настоящие категории из БД, чтобы EF не пытался создать их заново (`EFNoteRepository.cs:191-207`).

### SOLID — честно по каждой букве

- **S (Single Responsibility — одна причина для изменения).** Выполняется в основном: модели хранят данные, репозиторий — доступ к БД, контроллер — обработку запроса, представление — отображение, `NoteContext` — соответствие БД. Слабое место: `EFNoteRepository` обслуживает и заметки, и категории (один интерфейс `INoteRepository` задан заданием), а `NoteController` содержит вспомогательные методы (`SortAndLimit`, `FillStat`) — их можно вынести в отдельный сервис.
- **O (Open/Closed — открыт для расширения, закрыт для изменения).** Выполняется: новую реализацию хранилища можно добавить и подключить в `Program.cs:29`, контроллеры не меняются. Слабое место: `switch` в `SortAndLimit` (`NoteController.cs:243`) придётся менять при новом поле сортировки.
- **L (Liskov — подтип заменяет базовый тип).** Выполняется: любой `INoteRepository` (в т.ч. `EFNoteRepository`) можно подставить вместо интерфейса без изменения поведения контроллеров: методы возвращают `bool`/коллекции по единому контракту. Других иерархий наследования, кроме `Controller`, `DbContext`, в проекте нет.
- **I (Interface Segregation — много узких интерфейсов лучше одного широкого).** Выполняется частично: интерфейс `INoteRepository` один и «широкий» (8 методов и для заметок, и для категорий) — он задан заданием. Идеально было бы разделить на `INoteRepository` и `ICategoryRepository`, тогда `CategoryController` не зависел бы от методов заметок.
- **D (Dependency Inversion — зависеть от абстракций).** Выполняется полностью и это главный пункт: контроллеры зависят от `INoteRepository` (`NoteController.cs:20`, `CategoryController.cs`), а не от `EFNoteRepository`/`DbContext`; конкретный класс выбирается в одном месте — `Program.cs:29`; зависимости передаются через конструктор (Constructor Injection).
